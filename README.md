# 工业无线温振监测系统

面向 WTVB01-BT50 温振传感器和 EW-DTU02 蓝牙转串口网关，目标运行环境为 Windows 11 x64。

## v0.6.8

真实 EW-DTU02 串口模式默认并发上限为 3 台，已登记设备可以超过 3 台并按采集时长逐台轮换。单条 AT 回复超时会先尝试重新查询网关连接表；设备详情现为全屏页面，含运行期单设备断开/恢复和历史数据（1 小时至 7 天、自定义区间、分页表格、CSV 导出）。详见 [版本说明](RELEASE_NOTES.md)。本版尚未完成现场长时间硬件验收。

## v0.6.7

修复 v0.6.6 新增设备后“已连接但无数据”、频繁重新发现、最终断开事务误锁住整个队列的问题。每次建立 BLE 连接后先观察至少 5 秒有效温振数据，再添加下一台；20 秒没有首条有效数据或持续断流时，只释放该异常连接，记录原因、延后重试并轮换兼容参数。当前批次中已发现的失败设备可利用空闲通道重试，不为它反复断开正常设备。

移除 MTU23 兼容尝试：实测该组合可能仅输出每帧前 20 字节。解析器不会再把连续的 20 字节帧头拼成伪造的 32 字节样本，真实的分片续包仍可重组。运行中新增登记已被网关连接的设备时，会同步其连接状态，避免有通知却一直显示排队。

断开操作使用独立的 15 秒等待窗口。网关先回 OK 时只表示收到指令，不等于已经断开；收到确认后不再重复发送，必须等待匹配设备的断开事件及结束标记。断开过程中的 ERROR 也保留原事务等待迟到结果，超过完整窗口仍不能确认才报告阻断错误。重开软件查询多路连接时，收齐每台设备的完整记录后再继续调度。

新增或启用设备会触发一次重新发现；后续自动发现等待已有批次获得完整采集时间，不再用扫描开始时的 30 秒计时打断刚建好的连接。诊断仍保留坏通知、非 ASCII 字节和首个真实阻断错误。

每次停扫后通过 `AT+SCAN?` 回读扫描状态。确认停止才开始连接；仍在扫描时有限重试，不再仅凭裸 OK 推断扫描已经停止。

本版没有改写传感器采样配置，也不会自动恢复网关出厂设置。BLE 已连接不代表传感器已经输出数据；请结合“采集中”和最近有效样本判断。详见 [版本说明](RELEASE_NOTES.md)。

### v0.6.6

引入批次发现后停扫、逐台建链和并行采集；本版修正新增设备、无数据连接、迟到断开以及多条连接列表的处理。

### v0.6.5

引入“扫描发现 → 停扫 → 采集”，并增加通知长度校验及诊断计数。v0.6.6 保留这些改动，修正其多通道调度和优先切换条件。

### v0.6.4

修复现场四字段断开通知未识别、断开后仍计入连接数的问题；查询仅返回 `+CNB:1` 时，只有同一查询窗口内收到唯一 MAC/handle 的有效通知载荷，才据此确认现有连接并继续启动。缺失或矛盾证据仍报告超时。

### v0.6.3 连接兼容

静态核对用户提供的 v0.4 EXE 后，确认其使用扫描地址 + MTU247 + 配对扩展参数。本版将该完整组合加入并置于首位；此前 v0.6.2 未包含配对与扫描地址的组合。详见 [v0.4 对照记录](docs/v04-comparison.md)。这不是完整回退，仍保留新版串口队列、日志和 MAC 编辑。
