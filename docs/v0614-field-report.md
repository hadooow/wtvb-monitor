家里 v0.6.13 日志：10:46 首先选择 COM3，三次发生串口写超时。改为 COM5 后网关正常回复型号 EW-DTU02-M、固件 V1.5(2507081320)，扫描成功；E95BEA0C2DE1 输出有效温振数据约 80 秒后出现断开码 8。D60 的配对/扫描地址及普通/自动地址连接失败；FE6 后续也超时。

## 本机硬件证据

Windows 端口枚举：COM5 为 FTDI USB Serial Port；COM3 为 BTHENUM 蓝牙虚拟串口。它们不能互换。自动选择 USB 串口不会把设备描述当作已经确认的网关型号。

本机 Windows 蓝牙扫描确认全部 5 台为 WTVB01-BT50：

|---|---|---:|
|原 WTVB01-BT50|FE:6D:F4:07:B3:E4|2849|
|桌面 2|E9:5B:EA:0C:2D:E1|2825|
|桌面 3|D1:69:C0:65:9E:A8|2898|
|桌面 4|C5:AE:32:3B:69:BC|2802|
|桌面 5|D6:0F:8E:9D:18:99|2779|

11:10:54–11:15:45（北京时间）的电脑直连驱动测试，使用实际扫描得到的 BLEDevice、关闭服务缓存、不主动配对，订阅 FFE5 服务中的 FFE4 通知；5 台均连接成功，各输出约 24–26°C 的有效数据，没有断开事件。该测试没有向传感器写入寄存器。

同位置 COM5 网关 D60F8E9D1899 使用普通连接/网关默认间隔（MTU247、40 秒、开启通知）仍返回 DISSCONNECT/BLE 34，没有有效样本。只有这一个网关方案在本次本机对照中实测，不能推广为所有网关方案均失败，也不能证明具体网关固件内部原因。

## 本版修改

- 默认现场配置选 Windows 电脑蓝牙直连、5 路、32 字节；保留网关模式及已有连接方案。
- 暂停、删除或停用请求在直连扫描/连接忙碌时保留，按连接代次执行；旧请求不影响后来重新连接的设备。
- 每台先持续收到至少 5 秒有效数据，再添加下一台。无数据仍按原有 20 秒窗口隔离并退避重试。
- 新数据库及旧数据库一次性补入 4 个新桌面 MAC，FE6 已属原预置；保留用户原名称、阈值、启用状态和历史，尊重后续删除。
- 串口列表显示设备描述，阻止蓝牙虚拟串口。自动选口要求唯一 USB 端口；多个时需要用户选择。
- 温振数值区分实时与最近有效值，后者显示观测时间且不计入采集中/当前报警；缺失值不伪造为 0。
- 直连路径显示广播、BLE 连接、有效数据诊断；网关连接失败保留错误码。

## 验证范围

175 项自动化回归测试与 Windows EXE 模拟采集自检用于验证软件流程；五台驱动实测用于验证当前桌面硬件链路。发布包另做真实五台采集、数据库写入和暂停/重连验收，结果随用户交付记录保存。

车间 CBF 系列、无线安装条件、长时间通电稳定性及全部网关连接方案没有在本机验收。桌面成功不替代车间验收，长期稳定性需要现场运行记录。
