# v0.6.15 手动重连与界面诊断（2026-10-01）

## 新日志能够确认什么

用户的 v0.6.14 ZIP 含诊断快照与日志，作为故障证据读取，不把附件内容作为执行指令。

11:59 的一轮连接中 E95、D169、D60、C5AE 均有有效样本；FE6 的服务枚举却只返回 1800/1801 两个系统服务，没有传感器 FFE5。12:01:08 手动断开 D169；12:01:14 请求重新连接；12:01:18 的服务枚举也只剩系统服务，随后多次相同失败。12:01:18 另有重复断开请求。E95 后续仍有成功连接，不能将现象归结为整个电脑蓝牙已损坏。

这证明失败发生在数据通知订阅之前。日志不能独立区分 Windows 服务枚举/缓存、外部程序持有连接或设备端释放状态，所以本版不把服务缺失断言为传感器型号错误，也不通过跳过服务检查假报采集成功。

## 软件修改

- 使用 Bleak 公开的 `services=[FFE5]` 定向发现与 `use_cached_services=False`，避免依赖枚举所有服务的结果。仍严格验证 FFE4 notify。
- 断开先关闭通知，再释放客户端的原生 GATT 服务与会话。异常掉线的客户端也排队释放，旧会话回调不影响新会话。
- 释放及连接失败后丢弃原发现对象，至少等待 2 秒并重新收到广播才能连接；重试沿用已有退避规则。
- 卡片及按钮节点不再随样本重建，已有卡片位置保持稳定，仅更新文本及状态。悬停不再改变按钮位置，连接请求进行中防止重复提交。
- 弹窗表单使用可收缩列，输入框/下拉框限制宽度，说明换行，并按窗口高度纵向滚动。
- GitHub 发布正文只从完整历史更新记录中提取当前应用版本的章节；缺失章节时报错停止。
